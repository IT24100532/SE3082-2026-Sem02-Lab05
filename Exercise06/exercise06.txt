Exercise 6: element-wise multiplication with strip mining
Run on: MacBook Air (Apple Silicon, 8 cores), Apple clang + libomp. Build with: make
Program: exercise06.c    C[i] = A[i] * B[i], N = 1,000,000 (float arrays)

How it works:
- Strip mining: the one big loop is split into two loops. The outer loop steps through
  the array one strip at a time (is += STRIP). The inner loop handles the elements of
  that strip. The last strip is cut short if N is not a multiple of the strip size.
- OpenMP: "#pragma omp parallel for schedule(static)" on the outer loop gives each
  thread its own set of strips.
- SIMD: "#pragma omp simd" on the inner loop tells the compiler to multiply several
  elements in one instruction.
- Strip size = 1024. It is a multiple of every common SIMD width (4 floats for
  SSE/NEON, 8 for AVX, 16 for AVX-512), so every strip is made of whole vectors.
  One strip of A, B and C is 3 x 4 KB = 12 KB, which fits in the L1 cache.

Output (1000 repeats of the whole multiplication):
N = 1000000, strip size = 1024, threads = 8, repeats = 1000
serial:       time = 0.131302 s, checksum = 499999500000.0
strip-mined:  time = 0.104737 s, checksum = 499999500000.0
results match, speedup = 1.25x

The checksums are the same, so the result is correct. The speedup is small
(about 1.0x to 1.5x, and it changes from run to run) for two reasons: the compiler
already vectorises the plain serial loop, and this job is limited by how fast memory
can be read and written, not by the CPU.

I first tried a strip size of 8 (exactly one AVX vector). It gave the right result but
was slower than serial (0.37x on 1 thread, about 1.0x on 8 threads), because the
bookkeeping for every tiny strip costs more than the 8 multiplications inside it.
