Exercise 7: Area of the Mandelbrot set
Run on: MacBook Air (Apple Silicon, 8 cores), Apple clang + libomp. Build with: make

Programs:
- area.c           the provided serial code (unchanged)
- area_parallel.c  parallel region started before the main loop; each thread works out
                   its own equal share of the outer loop with omp_get_thread_num() and
                   omp_get_num_threads()
- area_schedule.c  extra exercise: "parallel for" with schedule(runtime)

Variables in the parallel region:
- numoutside: reduction(+). Each thread counts in its own copy and the copies are added
  at the end. Without this, threads would overwrite each other's counts (a data race).
- i, j, iter, ztemp, z, c, id, nthreads, istart, iend: private. Every thread needs its
  own loop counters and its own z and c values.
- team: shared, written once by a single thread so it can be printed afterwards.
- NPOINTS and MAXITER are constants, so they are safe to share.

Results (equal split of the outer loop):
serial (area.c):  Area of Mandlebrot set =   1.50926625 +/-   0.00075463   time = 6.65 s
1 thread:         Area of Mandlebrot set =   1.50926625 +/-   0.00075463   time = 7.02 s
2 threads:        Area of Mandlebrot set =   1.50926625 +/-   0.00075463   time = 5.91 s
3 threads:        Area of Mandlebrot set =   1.50926625 +/-   0.00075463   time = 4.25 s
4 threads:        Area of Mandlebrot set =   1.50926625 +/-   0.00075463   time = 3.24 s

The area is identical for every thread count, so the parallel code is correct.
The time does not drop evenly (2 threads are only 1.2x faster). Every thread gets the
same NUMBER of points, but not the same amount of WORK. Points inside the set need all
2000 iterations, and points far outside stop after a few. The threads that get the
columns through the middle of the set do most of the work while the others finish
early and wait (load imbalance).

Extra exercise: other ways of mapping iterations to threads (4 threads, OMP_SCHEDULE):
static      3.74 s   (one big block per thread, like the equal split)
static,1    2.39 s
static,10   2.09 s
dynamic     2.06 s
dynamic,10  1.89 s
guided      2.09 s

All give the same area. Small chunks (static,1 / static,10) or dynamic scheduling mix
the heavy and light columns between the threads, so the work is balanced. The best
(dynamic,10) is 3.7x faster than one thread, against 2.1x for the equal split.

Note on the last digits: the compiler may combine a multiply and an add into one
instruction (FMA), which rounds slightly differently. Points on the edge of the set
are very sensitive to rounding, so a different compiler or machine can give a slightly
different area in the last digits (with FMA turned off, -ffp-contract=off, this code
gives 1.50928453). The difference is far smaller than the +/- 0.00075 error estimate,
and the result is always the same for every thread count on the same machine.
